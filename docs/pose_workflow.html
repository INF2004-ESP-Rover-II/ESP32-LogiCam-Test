Distance and bearing from ArUco markers

How the pieces connect, then each part in order: what to run, where, what to press, and how you know it worked. Everything below runs on the MacBook, from the software/ folder, with the ESP32 streaming at 172.20.10.5.

Hardware One-off setup Runs live

Procedure

0
MacBook · once

Get the files and libraries in place

  • Copy calibrate.py, marker_pose.py, pose_stream.py and range_test.py into the MacBook's software/.
  • Install the libraries: pip install opencv-contrib-python numpy (contrib, for cv2.aruco).
  • Power the ESP32 with the webcam in the OTG port. Close any browser tab on /stream: the board serves only a few connections.
Done when python3 range_test.py prints Stream OK: WxH. Note that resolution; you calibrate at it.
1
MacBook + printer · once

Make the chessboard

python3 calibrate.py --make-board

Writes chessboard_9x6.png: 10 × 7 squares, which is 9 × 6 inner corners. Print at 100% scale and tape it to card or a clipboard so it stays flat. A tablet showing it full-screen also works; turn the brightness down to avoid glare.

2
MacBook + ESP32 stream · once per camera or resolution

Calibrate the camera

python3 calibrate.py
  • Hold the board in front of the camera. When the corners are drawn in colour and the label says BOARD FOUND, press Space.
  • Take about 20 views. Cover the whole frame (centre, edges, all four corners), near and far, and tilted about 30° left, right, up and down.
  • Press c to calibrate and save (needs at least 12). q quits without saving.
Done when it prints RMS reprojection error below 0.5 px and saves camera_calib.json. From 0.5 to 1.0 is usable; above 1.0, retake with sharper, flatter views.
Redo it if you change the webcam, the stream resolution or its focus. A mismatched resolution with the same aspect ratio is scaled automatically, with a warning.
3
Ruler · once per marker print

Measure the printed marker

Measure the side of the marker from the outer edge of the black border to the outer edge on the other side, in millimetres. Leave out the white margin. Distance scales directly with this number: 5 mm wrong on a 100 mm marker means 5% wrong on every distance.

Also note the dictionary your markers were printed from. The scripts default to DICT_6X6_250. If nothing is detected, run dict_finder.py.

4
MacBook + ESP32 stream · every session

Run live distance and bearing

python3 pose_stream.py --marker-mm 100
# other dictionary:
python3 pose_stream.py --marker-mm 100 --dict DICT_4X4_50

Each marker gets an outline, 3D axes and a label like ID 7 85.3 cm +4.2 deg. The terminal prints the same twice a second.

FieldMeaning
range_mmStraight line, lens to marker centre
forward_mmDepth along the camera's axis only
bearing_deg0 = dead ahead, + = right, − = left. Camera frame, not rover heading
reproj_err_pxHow well the pose fits the corners. Under ~1 px is good
side_pxMarker size in pixels. Small means far and less reliable
5
Tape measure + ESP32 stream · for the B1 handoff

Measure the error

  • Mark distances on the floor, for example 50, 100, 150 and 200 cm from the lens, straight ahead.
  • At each one, with pose_stream.py running, press s, then type the true distance in mm and the true angle.
  • Repeat a few at about ±20° to check bearing. Then repeat in the real arena lighting.

Every press adds a row to pose_log.csv with true vs measured values, plus the reprojection error, pixel size, resolution and marker size.

Done when you have a table of error against distance and angle. This is the "measured detection error" B1 asked for, and it tells you the range where readings are trustworthy.

After this

Distance and bearing are now measured, but they only appear on screen. B1's priority-1 list still needs vision_publisher.py: the same readings sent once per frame with frame_seq, timestamps, a plain/junction type from the agreed ID table, a valid flag based on reproj_err_px and side_px, camera health (ok, no marker, stalled, disconnected), and a --record option for replayable samples.
